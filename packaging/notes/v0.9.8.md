0.9.8 fixes the weaknesses found by an adversarial review of Guardian on
2026-11-09, published as advisory GHSA-vhff-xvwq-q499 (medium). Update with
`./install.sh` or the upgrade check as usual; nothing needs to change in
your settings.

## Security fixes

- **The sweep's secret redaction kept the setting that loads code.** Values of
  names with KEY, PASS or TOKEN in them were hidden even when they load code
  (`GIT_CONFIG_KEY_0=core.fsmonitor`, `RESTIC_PASSWORD_COMMAND`, git's
  `core.askPass`), so neither the local rules nor the AI saw the payload. Only
  real secrets are masked now; code is always sent as it is.
- **The upgrade check starts again with a clean environment.** A stray
  `BASH_ENV`, exported function, `TAR_OPTIONS`, `GIT_*` or `LD_PRELOAD` in the
  caller's environment could change what was verified or built. The check now
  runs with only the variables it needs.
- **The sweep's live checks are bounded.** Any account could make root's
  collector hash enough large files to be killed after 30 minutes, leaving no
  results and no alerts. The files and bytes read are now capped, and what a
  cap left out is reported.
- **Accounts can no longer crowd out root's results.** One account could fill
  the 5,000-item cap and push out the unit in its home that stands in for the
  sweep's. The results are now capped per account and per kind and ranked by
  who could make each item, and the bar says when the results are too large to
  read.
- **The local rules read a line as the shell reads its words.** Commands
  spelled so the shell runs the same thing (`cu''rl`, `c\url`, `'rm' -rf /`,
  `rm${IFS}-rf`) slipped past them, and the pacman gate's exemption for
  Guardian's own removal let a glued command through
  (`rm -f /etc/omarchy-guardian;ufw disable`).
- **Themes and plugins are remembered by their repository as well as their
  name.** A fork with the same name was reviewed as an upgrade of the approved
  version.
- **Lower findings.** File names and tool output can no longer write escapes
  to the terminal. A Claude Code run that timed out mid-review counts as out
  of time, not as an unavailable reviewer. The review walk stops at 256
  directories deep instead of crashing. The bar no longer reports the Bash
  interceptor as loaded after a later line removes it. A forged makepkg
  listing can no longer hide the sources the build fetches.

## Worth knowing

- Baselines of themes and plugins recorded by 0.9.7 or earlier are keyed by
  name only and are no longer used, so the first update of each theme and
  plugin after upgrading is a full review.

- A program already running as you can replace an archive in your own
  directory between the pacman hook's review and pacman opening it. The docs
  now say so and give the way around it: copy the archive somewhere only root
  can write, then `sudo pacman -U` that path.
- The local rules guess how bash reads a line from its text. Some spellings
  are still left to the AI review, listed in `docs/local-rules.md`.
- In agent entries, a quote inside `$(…)` inside double quotes can leave the
  line's reading open, so a key later on that line may be sent to the AI. This
  is documented in the redaction module.
